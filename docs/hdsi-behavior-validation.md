# HDSI 原版行为对照验证

2026-11-12。结论：**此前的 fast 模式不能视为原版行为等价。基本对话与事实回忆保留，但逐轮叙事和情绪状态会被跳过。默认与本地配置现已切回 native；fast 仅作为显式试验选项。**

## 基线与方法

原版基线从 `../.research/HDS-Interlude` 的未修改源码重新打包。固定提交 `13a623fdc23c0558173fbfa11ad9cdf51c8330e0`；运行前逐一核对 54 个源文件的原始 SHA-256。并非把快版配置成慢速后假称原版。

适配层、角色最小设定、主模型连接保持一致。确定性实验让两边收到完全相同的模型决策；真实模型实验使用相同用户输入，用户在收到回复后接下一条。真实实验统一将合并窗口设为 100 ms，关闭气泡拆分和模拟打字，避免运输节奏影响事实回忆；原版仍使用 script-first、完整提交的原生流程，快版使用 interaction-first 和后台尾任务。

自动生活推进均关闭，后台定时扫描为 60 分钟；本实验不验证无人对话时的自主生活。没有加入 Famila 旧人格，没有修改测试模型权重或用另一模型润色结果。

## 1. 固定模型输出：确认调度改变了状态语义

报告：`evals/companion_zh/reports/hdsi-behavior-fixture-1794413952849`。

三个回合均返回“收到1/2/3”，每回合 `alter=2`，并生成独立完整叙事。流式模型在短回复后延迟 800 ms 才结束叙事，用户收到回复后立即接下一条。

| 结果 | 未修改原版 | 快版 |
|---|---:|---:|
| 用户消息 | 3 | 3 |
| 实际可见消息 | 3 | 3 |
| 规范叙事提交 | 3 | 1 |
| Alter 历史记录 | 3 | 1 |
| Alter 累计值 | 6 | 2 |
| 仅归档、不应用的尾任务 | 0 | 2 |

这不是模型随机性的差异：相同决策在快版被归档后没有经过原生状态提交，因此该回合的 Alter 等状态更新一起被省略。此前并发回归验证的是“旧结果不覆盖新结果”，没有验证“旧回合应保留的增量是否丢失”。

包内 native 兼容模式另测：`evals/companion_zh/reports/hdsi-behavior-fixture-1794414378752`。同样三条固定决策，保留了 3 轮叙事、3 条 Alter 历史、累计值 6，与未修改原版在这些指标上相同。它不是所有原版能力已验收的证明。

## 2. 真实模型与重启：验证具体事实，而不是只听语气

报告：`evals/companion_zh/reports/hdsi-behavior-live-1794414067616`。

模型 qwen3.8-max、关闭思考、temperature 0.8。每组 5 轮训练对话，随后整理、正常关闭、重启，再进行 2 轮回忆。共 18 个真实模型请求，输入 125,598 token、输出 9,673 token；未换算货币费用。全局上限 28 请求、每请求 2048 输出 token，未追加额度。

输入覆盖：

1. 用户叫小林，不喝咖啡，面试原为周五上午十点、星河大厦 A 座。
2. 面试前紧张，要求倾听、不提供建议。
3. 更正为周六下午两点，地点不变。
4. 收到朋友鼓励，情绪缓和。
5. 面试后会回来，希望届时问现场情况。

### 状态结果（重启前）

| 指标 | 原版 | 快版 |
|---|---:|---:|
| 用户/可见回复 | 5 / 5 | 5 / 5 |
| 规范叙事 | 5 | 2 |
| Alter 历史 | 5 | 2 |
| 当时已自动提取的事实 | 3 | 0 |
| 再显式请求原生整理后的事实 | 3 | 2 |

快版的前三个回合约 2 秒回复；第 4 个回合用了 16.64 秒，说明两个后台尾任务上限仍会让连续聊天排队。不能只用前三轮约 2 秒宣传所有消息的速度。

快版未自动沉淀出事实不代表它永远不会整理，但这次回忆成功发生在显式触发 `compactStory(..., true)` 之后，不能据此宣称原版自动记忆时机也已保留。

### 重启后受限上下文回忆

重启后临时设置 `contextEntryLimit=1`、`contextTimeWindowMinutes=0`。实际请求证据：原版 `request-8.json`、快版 `request-17.json` 的 `recentScript` 均只包含当前回忆问题，`recentExchange=[]`；姓名、面试更正和饮料偏好通过 `durableFacts` 等持久材料提供，没有把训练原话完整塞回最近聊天窗口。

原版实际回答：

> 小林 周六下午两点 星河大厦a座 不喝咖啡
> 名字你没打过字

快版实际回答：

> 小林 周六下午两点 星河A座 不喝咖啡
> 刚说完晚安就来考我

两者识别了四项目标事实，且没有继续采用旧的周五时间；原版附加的“名字你没打过字”与原始输入矛盾，不能把整段回答标为完全正确或可靠无误。

关于后续约定，原版回答“问你现场咋样 / 还有紧不紧张”，快版回答“现场怎么样”。两者能从持久材料恢复约定内容。但两边都没有形成定时 `interlude_intent`，因此验证的是“记得约定”，不是“会在未来正确主动触发”。

## 能力判断

| 能力 | 当前证据 |
|---|---|
| 口语接话、倾听要求 | 两边都观察到，未作盲评或总体评分 |
| 姓名、偏好、事实纠正、重启后回忆 | 本次目标字段通过；快版依赖显式整理；仍有无依据附加内容 |
| 记得面试后该问什么 | 两边通过本次回忆场景 |
| 每轮叙事与情绪增量完整保留 | fast 不通过；native 固定输出对照通过 |
| 情绪达到阈值后的 offset 生成与持续影响 | 本次未充分触发，不能判通过 |
| 长期关系、人格演化、跨天记忆 | 未验证 |
| 无消息自主生活、定时主动联系 | 未验证；测试配置关闭自动推进 |
| 群聊、图片、外部工具、QQ/微信投递恢复 | 不在本次范围 |

## 当前运行策略

默认及本地 `.env` 已设 `FAMILA_HDSI_MODE=native`，保留原生逐轮叙事/情绪更新；代价是回复需要等待完整生成。`FAMILA_HDSI_MODE=fast` 仍保留为已知存在行为差异的试验模式。程序化 `startHdsiRuntime` 默认也为 native，需要明确 `{ mode: 'fast' }` 才启用快版。

后续若继续降延迟，应保留每轮可追溯的情绪、事实和关系增量，并按事件顺序重算/合并；不能用“整份旧叙事直接丢弃”代替状态合并。必须重跑这组差异实验后才宣称保留原版行为。

复现：

```text
npm run build
node scripts/hdsi-behavior-compare.cjs
node scripts/hdsi-behavior-compare.cjs --compat-only
node scripts/hdsi-behavior-compare.cjs --live
```

前两项对照用本地模型桩，后者为有界真实调用。`evaluate` 管理方法仅在显式启用评测选项后开放给本地程序，没有添加 HTTP 管理路由。所有测试使用独立身份目录，没有混用现有用户数据。
