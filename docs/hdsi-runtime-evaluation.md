- qwen3.8-max，读取 Famila 本地模型连接，关闭思考；HDSI 主采样默认 temperature=0.8。默认先前 Famila 回放是 0.9，不能将两者视为严格控制变量实验。
- 保留上游默认主提示词、风格、上下文结构、消息合并（2 秒）、分段、打字速度、Alter 等设置。
- 最小角色档案：姓名“测试角色”，描述“一位用中文交流的成年人。”，当代日常、家中，与用户日常聊天。HDSI 需要角色/世界框架，这与 Famila 的无人格基线不同。
- 关闭无消息时自动推进，后台扫描周期设为 60 分钟；原生按需侧任务仍运行，实际观察到时间/节奏侧任务和压缩事实提取。没有强制要求每轮回复。
- 每次运行代理上限 16 个请求，输出上限 2048 token/请求，30 秒请求超时、45 秒回合观察；记录所有实际用量，不自动追加额度。上游需要生成叙事，因此没有沿用纯聊天的 256 token 上限。

## 初步判断

这是原生运行时测试，不是从仓库取提示词的回放。当前样本证明项目能够接收入站、调用模型、持续写叙事、按事实上下文接话、记住刚提供的信息、提取事实、提交投递和取消过时气泡。

开发者阅读观察：具体、口语化的接话比之前 Famila 样本更明显，夜宵和告别没有长篇解释；但这只是少量场景，角色场景、采样与上下文都不同，不构成整体优胜结论。

主要问题也已实际出现：

1. 默认长叙事先行，首回复 14–21 秒，不满足我们此前约 1–3 秒的聊天目标；需要另做速度方案评估。
2. “外面冷 穿件外套”没有天气证据；“这个点还开着的也就烤串了”也没有营业情况证据。叙事容易将生活设定延伸为可见事实。
3. “吃完面脑子辣糊了吧”这类调侃是否舒服，需要用户盲评；口语化并不自动等于合适。
4. 连续 7 次回复计划为双气泡，尽管文字自然，段数仍可能形成模板。快速新消息正确取消了旧片段，但本次没有验证网络失败后的实际外部平台投递恢复。

Famila 默认逻辑与人格基线未因本次测试改变。下一阶段可以直接沿用这个适配器扩大原生 HDSI 样本，再决定借鉴其哪一部分；暂不继续人为追加 Famila 风格示例。
